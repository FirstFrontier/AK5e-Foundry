Authority: `03_chapter_3_character_classes.txt` — Defender L896–1219, Artshield L1223–1292, Dreadnought L1324–1361; Chapter 1 (Martial DC L211, Damage Reduction, "no Action required" L291); Chapter 6 L15/L79 (Elite, Leader). Stable IDs are those of the existing catalogues; this batch adds Actor workflows and does not replace packs.

Status: **implemented, unit-tested, and verified in a rendered Foundry 13.351 / dnd5e 5.3.3 session** (disposable `standard-test` World, 2026-10-10: 18/18 live checks plus a server-restart persistence check). Known limits are listed in `FOUNDRY_SMOKE_TEST.md` ("Defender, Dreadnought and Artshield live run") and `bugs/` (B-080 to B-087; B-086 is in `bugs/pending/`, the rest in `bugs/fixed/`).

Feature setup is opt-in: *Defender controls › Review feature setup* (or `game.ak5e.defender.preview/apply`) previews and applies. Nothing is imported on render, on class drop, or from a lifecycle hook. Feature setup enables Defender support, sets the Reaction maximum (2 from level 13), creates the managed effects below and adds the two native activities **only when missing**; an edited effect or activity is kept and reported. *Class progression setup* separately previews native HP, proficiencies, equipment, ASIs and all 42 Talent/Module choices. Operator Skills retain their existing chooser.

The 2026-10-11 finish increment is implemented and under fresh rendered acceptance testing. The earlier 18-check run above is a baseline, not validation of these new changes. A read-only source audit covered the entire 8,856-line Chapter 3 and the referenced Chapter 1/4 sections.

## Progression and Talent boundaries

`game.ak5e.defender.choices`, `previewProgression`, `applyProgression` and `openSetup` require an attached Defender class. Without a branch, the chooser offers Artshield or Dreadnought; an existing Defender branch is preserved. Source IDs govern missing feature Items. Exact generated class/branch/feature/talent records can reconstruct absent source Items; equipment requires installed Chapter 4 Items.

The elected GM applies the confirmed preview through the operation kernel. `flags.ak5e.defenderProgression` records immutable initial choices, applied HP/ASI levels, exact prepared plans and field receipts. Initial gains default to already included. Native light/medium/heavy armour and shield proficiencies preserve existing values; all-melee proficiency uses the custom note because native Simple/Martial groups include ranged weapons. Skills and tools retain higher authored proficiencies. Printed equipment or 1300 LMD (existing CP mapping) is granted once; two selections of one shield produce quantity two. Current HP, temporary HP, pools, authored Items and effects are preserved. Stale previews are refused; interrupted operations resume with the same ID and choices.

HP uses d12 (12 first, fixed 7 or entered d12 thereafter). ASIs at 4/6/8/10/12/16/19 use base scores, cap 20 and keep Legendary Might separate. Newly applied Constitution ASIs adjust included levels' maximum HP; new HP gains use the final Constitution modifier. This retains 5e's Constitution advancement rule; current HP does not increase.

Basic/Advanced Talents are chosen at 3/9. At 8/13 the player upgrades that original Talent or gains an additional different Talent, retaining the original. Each Item stores `flags.ak5e.defenderTalent = {sourceId,tier,moduleActive,active}`; the remaining 37 effects are clearly manual. Selection slots are preserved on repeat setup; retraining requires a separate table decision.

Recipient SP integration must be enabled. The GM independently observes actual HP updates; remote application hints require explicit GM provenance review if local native application evidence is absent. Missing facts never override known invalid outcomes. Trigger geometry and Skill state persist in GM-whispered evidence with opaque map keys; shared Actor flags and inspection omit snapshots. Player pickers exclude unseen Creatures. Missing range or Skill evidence can be explicitly confirmed by the GM for an exact recipient.

## Foundry V13 / dnd5e 5.3.3 facts used (read from the installed system)

- Save and concentration roll hooks pass `(config, dialog, message)`; setting `config.rolls[0].options.advantage|disadvantage` works before keybindings. An Art-card Save carries no item data: `config.event.target.closest("[data-message-id]")` finds its source. Native Arts Resistance and per-Art Spellshield origin lookup are live verified.
- Native Concentration saves do not identify who caused damage; the explicit receipt control supplies that correlation. An elected-GM claim precedes the native dialog; cancellation releases it, and only a new evaluated native CON Save message by that claim owner completes it. Known Art concentration effect instances must remain active.
- Native 5.3.3 target descriptors carry Actor UUIDs. The live Crownsplitter `preRollDamageV2` payload has `message.data.flags.dnd5e.targets`, while direct `message.flags` is absent. Unknown/mixed tiers stay guided.
- `system.abilities.<k>.value` is not clamped to `max`; Legendary Might therefore uses an explicit DOWNGRADE change (inferred from Foundry's priority order; **confirmed live 2026-10-10**: STR 18, 20 and 22 became 24, 26 and 26).
- `system.bonuses.mwak.damage` accepts dice, `@prof` and typed `[force]` flavours and applies to attack-activity damage index 0.
- Roll formulas have no ternary or comparison; level scaling uses `min`/`floor` arithmetic and a parenthesised dice count.
- `dnd5e.postUseActivity(activity, usageConfig, results)` and `preUseActivity` (return `false` to cancel); spell detection via `activity.item.type === "spell"`.
- Native `stunned` and `frightened` statuses exist; Stunned carries Incapacitated.
